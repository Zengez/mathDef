## What required repair

1. **Concurrency across workflows.** The Stage 5 start, link-batch and no-link/disposition workflows originally used separate GitHub Actions concurrency groups. Parallel runs could work from stale snapshots or conflict when rebasing. All now use `mathdef-stage5-reconstruction-writes`, `cancel-in-progress:false`, and refresh `origin/main` before reading/writing current research state. The start workflow can be replayed after initialization without resetting an existing ledger.
2. **Write-before-validation.** A rejected relation submitted against a previously held/no-link formulation could formerly append an edge before noticing the incompatible review. `stage5_review_gate.py` now checks all target identities, source anchors/citations, review compatibility and existing ID collisions **before ingest**, including for multi-edge batches. Regeneration after interruption is idempotent for identical records. Review-ledger rewrites now use fsync + atomic replacement.
3. **Seal and audit weakness.** The gate previously ensured that relations existed and had a screened state but did not fully recheck the stored edge provenance and source phrase during later `--audit` / `--seal`. It now revalidates all existing relationships, including source/target URLs, source phrase, review type and editorial rationale. The production-independent corrected workspace also blocks `Workspace.seal("relations")` until **every** one of the 431 formulations has an individually reasoned, terminal disposition.
4. **Semantic types conflated.** Three previously screened records were not defensible as mere `definition_uses` dependencies: a formally étale map implies formal smoothness and formal unramifiedness (two implications); finite projectivity is equivalent to finite local freeness (one equivalence). Their same preserved IDs and endpoints are now explicitly typed `logical_implication` or `equivalent_characterization`. The independent preview displays them as navigable related results, **not** recursive prerequisites. All 47 relationship records are preserved.
5. **Insufficient negative-path regression tests.** The isolated suite now tests failed ingest without partial writes, stale or tampered edges rejected during audit, direct premature sealing rejected, separate mathematical relation types, no-link traceability, and safe replay. All 48 tests passed in the healthcheck run.

## Important boundaries and residual risks

- The execution audit verifies **record coverage, source-ID provenance, review labels, code behavior and restart protection**. It does not claim independent mathematical peer review or fresh manual verification of all original Stacks pages. The Stage 5 reasons compare independently authored Stage 3/4 source-backed formulations and remain assistant-screened candidate relationships (`human_verified:false`).
- `no_supported_target` means *no suitable screened meaning is currently present in this limited reconstruction*, not that the prerequisite has no mathematical definition anywhere. The held vector-space/abelian-group case is correctly unresolved because its PlanetMath acquisition was blocked. Wave 2 should revisit missing-target leads.
- A good rationale and exact phrase do not prove a proposed mathematical edge is correct. Later context/synonym/definition audits and mathematical editorial review must assess semantic nuances, especially the meaning of equivalent formulations and logical implications. Future link batches should use the three explicit mathematical relation types rather than relabel implications as dependencies.
- Separate JSONL files do **not** form a fully transactional database if an interactive local script is killed between files; each file write is durable/restartable, and the GitHub-hosted workflow commits the collection only after a successful audit. On any interrupted or failed batch, rerun the same approved input, then `--audit`, and verify GitHub's committed checkpoint before reporting completion.
- Successful Python and Node syntax tests do not establish browser-level interaction or rendering correctness. Manually inspect recursive UI after Stage 6 publication.
- The first wave remains research-isolated. Do **not** inspect production mathDef definitions, variants or citations for missing links or compare against production until both waves are independently frozen.
